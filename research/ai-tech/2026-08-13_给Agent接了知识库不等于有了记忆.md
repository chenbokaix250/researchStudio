# 给 Agent 接了知识库，不等于它有了记忆

> **来源**: [X/Twitter @AndoRAG](https://x.com/AndoRAG/status/2087518480337928468)  
> **作者**: Ando（MemPlumb）  
> **发布日期**: 2026-08-12  
> **分类**: AI Tech  
> **标签**: Agent, RAG, Memory, 知识库, 记忆库

---

## 核心观点

很多人做 Agent，会把知识库和记忆库当成一回事。接个向量数据库，把公司文档塞进去，让 Agent 回答前先搜一下，就觉得它有记忆了。**没有。它只是能查资料了。** 这两件事听着像，做起来差很远。搞混了，Agent 迟早变蠢。

---

## 知识库管的是"外面有什么"

知识库干的事：存东西、建索引、检索。

产品文档、FAQ、操作手册、行业资料，全扔进去。用户问一个问题，系统搜一圈，把相关段落捞出来，丢给大模型组织回答。它回答的是**文档里写了什么**。

重要。但它只是在帮 Agent 查外部资料，跟 Agent 自己经历过什么、学会了什么，没半点关系。

---

## 记忆库管的是"它经历过什么"

记忆库干的事：记录、整理、复用 Agent 自己的经历。

用户上周投诉了什么，Agent 当时怎么处理的，结果好不好，用户后来又来了没有。这些是经验，得一点一点攒下来。记忆库要做的，是把这些经历存下来，下次碰到同一个用户、同一类问题，能拿出来用。

它回答的是**上次做对了什么，做错了什么，这次该怎么调**。

---

## 场景举例：同一个用户的三次投诉

一个电商客服 Agent，同一个用户一个月内来了三次：

**第一次**：用户说收到的手机屏幕有划痕。Agent 查知识库，找到退换货流程，指导用户拍照、提交、等审核。问题解决了。这次知识库帮上忙了。

**第二次**：用户说换回来的手机充不进电。Agent 又查知识库，找到充电故障排查指南，一步步排查。但 Agent **不记得**这个用户上周刚换过货。它不知道这人已经在经历第二次问题，不知道上次给了什么方案。它把这次当全新工单处理。

**如果它有记忆呢？** 它应该知道这用户上周换过一次，原因不同但体验不好，这次得更快响应，最好直接升级，别再让他走标准流程等三天。

**第三次**：用户又来了，第三台手机还是有问题。这时候人已经很愤怒了。Agent 如果有记忆，它应该看得到一条完整时间线，第一次划痕，第二次充电故障，第三次又出问题。它应该知道前两次怎么处理的，用户什么反馈，容忍度到没到极限。

这时候该做的，是直接触发升级，主动道歉，给超出标准流程的补偿方案。

**但一个只有知识库没有记忆库的 Agent，第三次还是把用户当第一次来的人。它每次都从零开始。**

---

## 为什么不能把经历也塞进知识库

很多人会想，把对话记录也存进知识库不就行了？**能存。但不好用。**

| 维度 | 资料 | 经历 |
|------|------|------|
| 性质 | 静态的，今天写好了，下个月还是对的 | 动态的，用户上周的偏好，这周可能就变了 |
| 冲突 | 通常不冲突，两份产品说明可以同时存在 | 经常打架，用户今天说喜欢辣，下周说吃清淡 |
| 版本 | 不需要版本管理，更新了旧版直接替换 | 需要完整版本链，旧版本不能直接删 |
| 来源 | 单一可信，产品文档就是产品文档 | 有来源差异，用户说的/Agent推断的/工具返回的，可信度不同 |

把经历塞进一个给资料设计的系统里，短期跑得动，长期知识库和记忆库一起烂。

---

## 知识库 vs 记忆库对比

| | 知识库 | 记忆库 |
|---|---|---|
| 管什么 | 外面有什么 | 经历过什么 |
| 回答什么 | 文档里写了什么 | 上次做对了什么、做错了什么 |
| 瓶颈 | 检索——怎么搜得准 | 治理——什么该记、什么该忘、冲突怎么办 |
| 像什么 | 操作手册，谁来了都翻同一本 | 老司机脑子里的经验 |

---

## 知识库 + 记忆库的正确配合

- **知识库**：每次回答前提供领域知识，包括产品参数、流程文档、行业规范。告诉 Agent 这件事的规则是什么。
- **记忆库**：每次回答前提供执行经验，包括用户历史、上次方案、失败教训、个人偏好。告诉 Agent 这个用户上次怎么了。

模型拿到两边的内容，加上当前对话，一起判断。

**只有知识库的 Agent**：能处理标准问题，但处理不了"同一个用户连续出问题"这种事。因为它不知道"上次"。
**只有记忆库的 Agent**：能记住用户历史，但连基本产品文档都不知道，也答不了具体问题。

---

## 记忆库做大了之后，问题才刚开始

知识库做大了，瓶颈在检索。换个更好的向量模型，加重排序，加混合检索，基本能缓解。

记忆库做大了，瓶颈在**治理**。几百条记忆的时候，怎么存怎么搜都行。几万条的时候，一堆问题冒出来：

- 旧记忆过期了但没人清理，还在被召回
- 同一个用户说过矛盾的话，系统不知道信哪个
- 三个月前的错误判断还在影响现在的回答
- 敏感信息被记住了但该删的时候没删
- 不同 Agent 之间的记忆没有隔离，权限边界全乱了

这些问题，换一个更好的向量库解决不了。**知识库的困难在于怎么搜得准，记忆库的困难在于什么该记、什么该忘、新旧冲突怎么办、记错了谁负责。这是治理问题，光靠检索解决不了。**

---

## 三层架构

```
知识库 → 管外面有什么（资料）
记忆库 → 管经历过什么（经验）
MemPlumb → 管记忆本身怎么治理（记忆的治理工程层）
```

知识库管资料，记忆库管经验，MemPlumb 管记忆本身怎么治理。三层各管各的，Agent 才不会越用越蠢。
