# 如何使用和管理这套 Obsidian 知识库

一套知识库真正的价值，不在于收藏了多少资料，也不在于图谱看起来多复杂，而在于它能否帮助我们更快地找到信息、形成理解，并推动实际工作。

这套 Obsidian 知识库采用 **PARA + 原子笔记 + MOC** 的混合结构：PARA 管理行动，原子笔记沉淀知识，MOC（Map of Content，主题地图）组织理解路径。它既能管理项目和日常记录，也能容纳 Research Studio 中积累的大量研究资料。

本文介绍如何从零开始使用它，以及怎样让它在长期使用后依然保持清晰。

## 一、第一次打开知识库

本地 Vault 路径为：

```text
/Users/bokaichen/Documents/New project/Obsidian Knowledge Base
```

在 Obsidian 中选择"打开本地仓库"，然后选中这个文件夹。打开后，建议先完成以下设置：

1. 打开 [[00 Home|我的知识库]]，将它加入书签。
2. 打开命令面板，运行 `Daily notes: Open today's daily note`，创建当天日记。
3. 确认左侧文件列表中能看到 `00 Inbox`、`20 Projects`、`40 Knowledge` 和 `50 Resources` 等目录。
4. 暂时不要安装大量第三方插件，先使用一周内置功能。

以后每次进入知识库，都可以从首页开始。

## 二、理解目录结构

知识库中的数字前缀用于固定目录顺序，不代表重要程度。

| 目录 | 用途 | 典型内容 |
|---|---|---|
| `00 Inbox` | 临时收件箱 | 灵感、链接、未分类记录 |
| `10 Journal` | 时间记录 | Daily Notes、周复盘 |
| `20 Projects` | 有完成条件的工作 | 发布网站、完成研究报告 |
| `30 Areas` | 长期责任领域 | 健康、职业、投资、家庭 |
| `40 Knowledge` | 自己理解后的知识 | 观点、方法、概念关系 |
| `50 Resources` | 外部参考资料 | 文章、书籍、Research Studio 报告 |
| `60 People` | 人物上下文 | 联系人、合作记录、待跟进事项 |
| `90 Archive` | 已结束内容 | 完成项目、失效资料、不活跃领域 |
| `99 System` | 系统文件 | 模板、附件、Bases、使用指南 |

判断笔记放在哪里时，不必追求理论上的完美分类，只需判断它现在的主要用途。

## 三、日常使用：从捕捉开始

当你获得一个想法、一条链接或一段临时信息时，不要停下来设计复杂分类。先把它放进 [[00 Inbox/Inbox|Inbox]] 或当天的 Daily Note。

例如：

```markdown
- [ ] 研究 AI Agent 的记忆架构
- 看到一篇关于 Android 多屏控制的文章
- 想法：知识库应该把"材料"和"自己的结论"分开
```

捕捉的目标是低阻力。分类、改名和建立链接可以稍后完成。

每天结束时，用几分钟处理这些输入：

- 可以立即完成的事情，直接做掉。
- 有明确结果的工作，创建 Project。
- 需要长期维护的责任，放入 Area。
- 外部文章或报告，放入 Resources。
- 自己形成的观点，写成 Knowledge Note。
- 没有价值的信息，直接删除。

Inbox 应该是一个流动区域，而不是长期仓库。

## 四、使用 Daily Note 管理每天

Daily Note 是每天的工作台，而不是必须写成长篇日记。

建议每天记录四类内容：

1. 今天最重要的三件事。
2. 工作过程中发生的事件和简短记录。
3. 新产生的决策、问题与知识线索。
4. 明天开始工作的第一个动作。

一天结束后，不需要把所有内容整理得很漂亮。只需把仍然有价值的内容送到正确位置：任务进入项目，观点成为知识笔记，资料进入资源库。

## 五、用 Projects 推动工作

Project 是能够完成的目标。它应该描述一个结果，而不是一个宽泛主题。

好的项目名称：

- 发布个人网站
- 完成 Android 多屏控制研究报告
- 建立 Obsidian 知识管理流程

不够清晰的项目名称：

- 网站
- Android
- 学习 AI

创建项目时，在 `20 Projects` 中新建笔记，并插入 [[99 System/Templates/Project|Project 模板]]。至少填写三项内容：

- **期望结果**：项目完成后具体有什么变化？
- **成功标准**：怎样判断项目已经完成？
- **下一步行动**：现在可以执行的最小动作是什么？

项目的 `status` 使用以下值：

- `active`：正在推进。
- `on-hold`：暂时暂停，并应说明恢复条件。
- `done`：已经完成。
- `cancelled`：主动取消。

首页的 Projects Base 会自动显示活跃项目。完成后，将项目移动到 `90 Archive`，不必继续留在工作区。

## 六、用 Areas 维护长期责任

Area 和 Project 最大的区别是：项目有终点，领域只有维护标准。

例如，"完成年度体检"是项目，"健康管理"是领域；"发布一篇文章"是项目，"内容创作"是领域。

每个 Area 应写清楚：

- 这个领域保持良好时是什么样子？
- 当前状态与目标标准有什么差距？
- 哪些事情需要定期检查？
- 当前有哪些项目正在改善它？

不要为每个兴趣都创建 Area。只有当你愿意长期承担责任时，它才应该进入 `30 Areas`。

## 七、把资料转化为真正的知识

Research Studio 中已经同步了大量报告，它们位于 [[50 Resources/Research Studio Index|Research Studio Index]]。这些文件首先是"资源"，不等于已经成为自己的知识。

阅读一份报告时，可以按照以下流程处理：

1. 找到报告试图回答的核心问题。
2. 用自己的话写出三点摘要。
3. 标出真正改变自己判断的内容。
4. 把可复用观点拆成独立的原子笔记。
5. 在原子笔记中链接回来源报告。

例如，一份长报告可能最终产生这些原子笔记：

- Agent 的长期记忆需要区分存储与检索
- 自动验证循环比单次生成更能提高代码质量
- 投资研究应把事实、假设与决策分开记录

这些标题都是完整主张，可以独立理解，也能被其他项目和文章引用。

## 八、写好原子知识笔记

原子笔记不是越短越好，而是每篇只承担一个核心观点。创建时使用 [[99 System/Templates/Atomic Note|Atomic Note 模板]]，并回答四个问题：

1. 我真正想表达的主张是什么？
2. 为什么这个主张重要？
3. 有哪些证据、推理或限制？
4. 它与哪些已有观点、项目或资料相关？

知识笔记使用成熟度状态：

- `seedling`：刚记录，尚未充分解释。
- `budding`：已经补充证据和连接。
- `evergreen`：内容清晰、可复用，并会持续更新。

不要为了把所有笔记变成 `evergreen` 而反复润色。只需要在它真正被使用时继续完善。

## 九、用 MOC 组织主题

当某个主题积累了多篇笔记时，可以创建一个 MOC。MOC 不是自动生成的文件列表，而是你对这个主题的人工编排。

一个好的 MOC 通常包含：

- 主题正在回答的核心问题。
- 建议的阅读或理解顺序。
- 关键概念与核心笔记。
- 不同观点之间的冲突。
- 当前还没有答案的问题。

例如，未来可以建立：

- AI Agent MOC
- Android 车机系统 MOC
- 投资方法 MOC
- 个人知识管理 MOC

MOC 的价值在于呈现"你如何理解这个领域"，而不只是列出有哪些文件。

## 十、使用属性、标签和链接

三者分别解决不同问题：

- **属性**描述结构化状态，例如 `type`、`status`、`deadline`。
- **标签**描述跨领域的主题或使用场景，例如 `topic/ai`。
- **链接**表达具体笔记之间的真实关系。

不要用标签重复属性。例如已经有 `type: project`，就不需要再创建多个含义相同的项目标签。人物、项目和具体概念也更适合使用链接。

详细规则见 [[99 System/Guides/属性与标签规范|属性与标签规范]]。

## 十一、每周维护知识库

知识库不需要每天大整理，但应该每周恢复一次秩序。按照 [[10 Journal/Weekly/每周复盘|每周复盘]]，完成以下事项：

- 清空 Inbox。
- 确认每个活跃项目都有下一步行动。
- 完成、暂停或取消失去意义的项目。
- 回顾本周 Daily Notes。
- 把重要记录提炼为知识笔记。
- 检查 Areas 是否偏离维护标准。
- 将结束内容移到 Archive。

如果时间有限，优先完成前两项：清空 Inbox，确认项目下一步。

## 十二、归档而不是过度删除

项目完成、领域不再维护、资料暂时失效时，可以移动到 `90 Archive`。归档能够保持工作区清爽，同时保留历史上下文和已有链接。

以下内容可以直接删除：

- 明确重复的文件。
- 无法确认来源、没有独特价值的摘录。
- 已过期且没有历史参考价值的临时信息。
- 测试笔记和无意义的空文件。

归档不是垃圾桶。真正没有价值的内容不必永久保存。

## 十三、插件管理原则

当前 Vault 依靠 Obsidian 内置的 Daily Notes、Templates、Properties、Bases、Search 和 Backlinks 即可运行。

只有遇到明确问题后，再考虑安装插件：

- 需要日历浏览 Daily Notes：Calendar。
- 需要跨笔记查询任务：Tasks。
- 需要更快的固定格式捕捉：QuickAdd。
- 需要脚本化模板：Templater。
- 需要更强全文搜索：Omnisearch。
- 熟悉 Git 并需要版本记录：Obsidian Git。

一次只安装一个插件，实际使用一周，再决定是否保留。具体清单见 [[99 System/Guides/可选插件清单|可选插件清单]]。

## 十四、备份与同步

同步不等于备份。同步工具可能把误删同时传播到所有设备，因此必须保留能够恢复历史版本的独立备份。

最低建议是：

1. 工作电脑上保留当前 Vault。
2. 使用 Time Machine 或其他工具保存历史版本。
3. 使用 Obsidian Sync、可信云盘或私有 Git 远端保留异地副本。
4. 每季度实际恢复一次测试文件。

不要在 Vault 中保存密码、私钥、身份证件或其他高敏感信息。更多说明见 [[99 System/Guides/备份与同步|备份与同步]]。

## 十五、最小可持续工作流

如果所有方法看起来太复杂，只执行下面这套最小流程：

### 每天

1. 打开 Daily Note。
2. 写下三件最重要的事。
3. 临时信息进入 Inbox。
4. 下班前确认明天的第一步。

### 每周

1. 清空 Inbox。
2. 检查活跃项目。
3. 从本周记录中提炼一篇知识笔记。
4. 归档已经结束的内容。

只要持续执行这四步，知识库就会逐渐变成个人工作与思考的可靠外部系统。

## 结语

管理知识库的核心不是分类，而是持续完成三个动作：**捕捉有价值的信息、形成自己的理解、把理解用于实际行动。**

文件夹、属性、模板、Bases 和插件都只是辅助工具。衡量这套系统是否有效的最好标准，是它能否让你在需要时找到正确的信息、做出更好的判断，并更快地产生成果。
