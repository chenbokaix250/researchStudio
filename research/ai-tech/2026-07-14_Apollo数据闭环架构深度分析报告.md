# Apollo 数据闭环架构深度分析报告

## 一、数据采集存储概述

Apollo的数据采集存储系统是一个完整的端到端pipeline，基于Cyber RT分布式通信框架构建。核心设计思想是将自动驾驶产生的所有传感器数据、控制命令、感知结果、规划轨迹等以统一的自描述二进制格式(.record)进行持久化，支持完整回放和仿真验证。

---

## 二、核心数据结构

### 2.1 Record文件格式

Apollo使用自定义的`.record`二进制格式存储数据，文件结构如下：

```
┌─────────────────────────────────────────────────────────────┐
│                        Header (16 bytes)                      │
├──────────────┬──────────────┬──────────────┬────────────────┤
│  magic (4B)  │ version(4B)  │  header_size │   size (8B)   │
├──────────────┴──────────────┴──────────────┴────────────────┤
│                        Header Message                         │
│  (is_complete, begin_time, end_time, message_number,         │
│   channel_number, size)                                       │
├─────────────────────────────────────────────────────────────┤
│                     Chunk #1                                  │
│  ┌────────────────┬────────────────────────────────────┐   │
│  │ ChunkHeader     │  ChunkBody                          │   │
│  │ (begin_time,   │  (多个Message)                      │   │
│  │  end_time,     │                                     │   │
│  │  msg_count)    │                                     │   │
│  └────────────────┴────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────────┤
│                     Chunk #2                                  │
│                         ...                                   │
├─────────────────────────────────────────────────────────────┤
│                       Index Section                           │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ Index: channel_name → chunk_position mapping         │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**关键字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| magic | char[4] | 文件标识 "APLR" |
| version | uint32 | 格式版本 (1.0) |
| header_size | uint32 | Header长度 |
| size | uint64 | 文件总大小 |
| is_complete | bool | 是否完整结束 |
| begin_time | uint64 | 起始时间戳(ns) |
| end_time | uint64 | 结束时间戳(ns) |
| message_number | uint64 | 消息总数 |
| channel_number | uint32 | Channel数量 |

### 2.2 核心Proto定义

**Header Message** (`cyber/record/header.proto`)：
```protobuf
message Header {
    bool is_complete = 1;
    uint64 begin_time = 2;      // 纳秒时间戳
    uint64 end_time = 3;
    uint64 message_number = 4;
    uint32 channel_number = 5;
    uint64 size = 6;
    string major_version = 7;
    string minor_version = 8;
}
```

**Chunk结构** (`cyber/record/chunk.proto`)：
```protobuf
message ChunkHeader {
    uint64 begin_time = 1;
    uint64 end_time = 2;
    uint32 msg_count = 3;
}

message ChunkBody {
    repeated Message messages = 1;
}

message Message {
    uint64 time = 1;
    string channel_name = 2;
    bytes content = 3;
}
```

## 四、数据采集流程深度解析

### 4.1 录制启动流程

```
用户执行 cyber_recorder record -c /apollo/sensor/camera/front_6mm/image
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    Recorder::Start()                        │
│  1. 创建Node: "cyber_recorder_record_<pid>"                │
│  2. 解析白名单/黑名单channel正则                            │
│  3. 创建RecordWriter并Open文件                             │
│  4. 调用InitReadersImpl()订阅指定channel                   │
│  5. 注册拓扑变化回调(TopologyCallback)                      │
│  6. 启动进度显示线程                                        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   InitReadersImpl()                          │
│  遍历white_channels中的每个channel:                         │
│    - 创建Reader<RawMessage>                                │
│    - 设置回调: ReaderCallback(channel_name)                  │
│    - 动态监听新Writer加入                                   │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 消息写入流程

```
传感器发布消息到channel
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│                  ReaderCallback()                            │
│  - 接收RawMessage                                          │
│  - 提取channel_name, timestamp, content                    │
│  - 调用writer_->WriteMessage()                              │
└─────────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│              RecordWriter::WriteMessage()                   │
│  1. 查找/创建ChannelCache                                  │
│  2. 构造Message protobuf                                   │
│  3. 调用file_writer_->WriteMessage()                        │
└─────────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│           RecordFileWriter::WriteMessage()                  │
│  1. 检查当前Chunk是否已满                                   │
│  2. 如果满了: 写入ChunkHeader + ChunkBody                  │
│  3. 写入Index条目                                          │
│  4. 更新文件偏移量                                          │
└─────────────────────────────────────────────────────────────┘
```

## 十二、总结

Apollo的数据采集存储系统设计要点：

1. **统一格式**：`.record`二进制格式封装所有传感器和系统数据
2. **自描述**：Header包含完整的元信息，支持独立解析
3. **高效写入**：批量Chunk写入 + 共享内存传输
4. **灵活分片**：支持时间和大小分片，适配不同存储场景
5. **完整回放**：精确时间戳同步，支持任意时刻回放
6. **工具完善**：从录制到解析到转换的完整工具链
7. **仿真集成**：Dreamview无缝集成数据回放和仿真验证

这套系统支撑了Apollo从数据采集到模型训练再到仿真验证的完整数据闭环，是自动驾驶快速迭代的核心基础设施。
